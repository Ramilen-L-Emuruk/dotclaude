# C# コードレビュー基準

汎用的なレビュータイミング・重要度レベル・承認基準は [code-review.md](../common/code-review.md) を参照。本ファイルは C#/.NET 固有のチェックリストをまとめる。

## レビューチェックリスト

### C# スタイル

- [ ] 命名規約に従っていること（型・メソッド・プロパティは `PascalCase`、ローカル変数・引数は `camelCase`、private フィールドは `_camelCase`）
- [ ] `var` は右辺から型が自明な場合のみ使用していること
- [ ] 再代入しないフィールドに `readonly` が付いていること
- [ ] メンバー名の文字列リテラル参照が `nameof` に置き換えられていること
- [ ] 未使用の `using` が除去されていること（`ImplicitUsings` 有効時は暗黙に含まれる名前空間の重複記述も）
- [ ] コメントアウトされたデッドコードが残っていないこと

### XML ドキュメントコメント

- [ ] public API に `<summary>` が存在すること
- [ ] `<param>`・`<returns>`・`<exception>` の内容が実装と一致していること
- [ ] 説明が空のタグ（`<param name="x"></param>` 等）が残っていないこと

### null 安全性

- [ ] `<Nullable>enable</Nullable>` 下で警告を握り潰していないこと（`!`（null 免除演算子）の乱用・`#pragma warning disable` の放置）
- [ ] 外部入力・相互運用（P/Invoke・ネイティブ API）の戻り値を null チェックしていること

### リソース管理

- [ ] `IDisposable` を実装する型が `using` 宣言または `using` 文で解放されていること
- [ ] `IDisposable` なフィールドを保持する型自身が `IDisposable` を実装していること
- [ ] アンマネージドリソース（ネイティブハンドル・GPU テクスチャ・ファイルハンドル等）に解放漏れの経路がないこと（**例外発生時の経路を含む**）
- [ ] イベントハンドラの購読解除漏れがないこと（購読しっぱなしは参照が残りメモリリークの原因になる）

### 非同期処理

- [ ] `async void` がイベントハンドラ以外で使われていないこと（例外を捕捉できずプロセスが落ちる）
- [ ] `.Result` / `.Wait()` による同期待ちがないこと（UI スレッド上ではデッドロックする）
- [ ] `CancellationToken` が呼び出しチェーンを通じて伝播していること
- [ ] ライブラリ層の `await` に `ConfigureAwait(false)` が付いていること

### スレッド間の待ち合わせ

- [ ] `Monitor.Wait`/`Monitor.PulseAll` で待ち合わせる場合、[coding-style.md](../common/coding-style.md)「並行処理での待ち合わせ」を満たしていること（通知経路の網羅性・状態を変えないガードの扱い）
- [ ] `Monitor.Wait` のループ条件に、終了要求と状態リセットの脱出条件が含まれていること
- [ ] `lock` 内から外部コールバック（デリゲート・イベント）を呼ぶ箇所で、コールバック側が別のロックを取っていないこと（デッドロック源）

### UI（WPF / WinForms を使う場合）

- [ ] UI 要素への読み書きが UI スレッド上で行われていること（`Dispatcher.Invoke` / `InvokeAsync` 等）
- [ ] 毎フレーム・高頻度で実行される経路でアロケーションが発生していないこと

## エージェントの使い分け

C#/.NET には言語固有のレビュー専用エージェントを用意していない。汎用の `code-reviewer` に本ファイルの観点を明示して渡す。詳細は [agents.md](./agents.md) を参照。
